MySQL Syntax & Decision Sheet

MySQL: syntax and when to use what

Every clause with MySQL 8 syntax, plus the decisions the test checks: WHERE vs HAVING, which JOIN, JOIN vs subquery vs EXISTS, when to use window functions, and DDL/DML forms. Red Exam trap boxes mark the mistakes graders look for. Start with sections 1–2, then practise in the MySQL Practice Exam.

1The query skeleton & execution order

SELECT   [DISTINCT] col, expr AS alias, AGG(col)     -- 5  what to show
FROM     table1 t1                                    -- 1  where the rows come from
[LEFT] JOIN table2 t2 ON t2.key = t1.key              -- 2  combine tables
WHERE    row_condition                                -- 3  filter ROWS (no aggregates, no SELECT aliases)
GROUP BY col                                          -- 4  make groups
HAVING   group_condition                              -- 4b filter GROUPS (aggregates OK)
ORDER BY alias DESC                                   -- 6  sort (aliases OK)
LIMIT    [offset,] count;                             -- 7  cut
Logical order: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. Nearly every SQL error the test can ask about follows from it:
  • A SELECT alias in WHERE → Unknown column (SELECT hasn’t run yet). MySQL does allow aliases in GROUP BY, HAVING and ORDER BY.
  • WHERE COUNT(*) > 1 → Invalid use of group function (groups don’t exist yet). Use HAVING.
  • A window function in WHERE → error (windows are computed in SELECT). Wrap the query in a derived table and filter outside.
  • LIMIT without ORDER BY → the rows you get aren’t guaranteed.

3SELECT, aliases, DISTINCT, CASE

SELECT first_name, last_name FROM employees;
SELECT * FROM employees;                                   -- all columns (avoid in production: slower, fragile)
SELECT first_name AS name, salary * 12 AS annual_salary    -- AS is optional: salary*12 annual
FROM employees e;                                          -- table alias
SELECT `order`, `select` FROM t;                           -- backticks quote identifiers / reserved words
SELECT DISTINCT dept_id FROM employees;                    -- unique values (NULL counts as one)
SELECT DISTINCT dept_id, manager_id FROM employees;        -- unique COMBINATIONS of both columns
SELECT 'fixed text', 1 + 1, NOW();                         -- SELECT without FROM is valid in MySQL

SELECT first_name,
       CASE                                           -- searched CASE: first true WHEN wins
         WHEN salary >= 8000 THEN 'High'
         WHEN salary >= 5000 THEN 'Medium'
         ELSE 'Low'                                   -- without ELSE → NULL
       END AS band,
       CASE dept_id WHEN 1 THEN 'Eng' WHEN 2 THEN 'Fin' ELSE 'Other' END AS d,   -- simple CASE
       IF(email IS NULL, 'missing', 'ok') AS email_state                        -- MySQL IF(cond, a, b)
FROM employees;

CASE works anywhere an expression is allowed: SELECT, WHERE, ORDER BY (ORDER BY CASE status WHEN 'PENDING' THEN 1 ELSE 2 END), GROUP BY, and inside aggregates.

5NULL: rules and functions

  • NULL = unknown. Any comparison or arithmetic with NULL gives NULL: NULL = NULL → NULL, 5 + NULL → NULL, CONCAT('a', NULL) → NULL.
  • WHERE keeps only TRUE, so rows where the condition is NULL are dropped, including in <>: WHERE dept_id <> 1 doesn’t return rows with a NULL dept_id.
  • Aggregates ignore NULL (except COUNT(*)). GROUP BY puts all NULLs in one group. ORDER BY ASC puts NULLs first in MySQL.
FunctionMeaning
IFNULL(x, d)x, or d if x is NULL (MySQL)
COALESCE(a, b, c)first non-NULL argument (standard SQL, any number of args)
NULLIF(a, b)NULL if a = b, else a. Avoids division by zero: x / NULLIF(y, 0)
IF(x IS NULL, …, …)custom handling
CONCAT_WS(' ', a, b)concatenates with a separator and skips NULLs

Not in MySQL: NVL (Oracle), ISNULL(a, b) (SQL Server). In MySQL, ISNULL(x) takes one argument and returns 1/0.

6ORDER BY & LIMIT

ORDER BY salary DESC, first_name ASC     -- ASC default; second column breaks ties
ORDER BY 2 DESC                          -- by the 2nd selected column (allowed, less readable)
ORDER BY annual_salary                   -- SELECT alias is allowed here
ORDER BY email IS NULL, email            -- NULLs last (false=0 sorts before true=1)
ORDER BY FIELD(status, 'PENDING', 'SETTLED', 'CANCELLED')   -- custom order (MySQL)

LIMIT 10                 -- first 10 rows
LIMIT 20, 10             -- skip 20, take 10 (rows 21–30) = LIMIT 10 OFFSET 20
LIMIT 1 OFFSET 1         -- the 2nd row → "second highest" when sorted DESC (use DISTINCT for distinct values)

Page n with size s: LIMIT s OFFSET (n-1)*s. MySQL has no TOP and no FETCH FIRST.

Rule: every column in SELECT must be in GROUP BY or inside an aggregate (MySQL 8’s ONLY_FULL_GROUP_BY, error 1055). SELECT dept_id, first_name, MAX(salary) … GROUP BY dept_id does not give the top earner’s name. Use a window function or join back to the max.

-- chain: follow the keys
FROM students s
JOIN grades g  ON g.student_id = s.student_id
JOIN courses c ON c.course_id  = g.course_id
-- composite key
JOIN t2 ON t2.a = t1.a AND t2.b = t1.b

-- FULL OUTER JOIN emulation
SELECT d.dept_name, e.first_name FROM departments d LEFT JOIN employees e ON e.dept_id = d.dept_id
UNION
SELECT d.dept_name, e.first_name FROM departments d RIGHT JOIN employees e ON e.dept_id = d.dept_id;
ON vs WHERE with a LEFT JOIN. A condition on the right table in WHERE removes the NULL rows and silently turns the LEFT JOIN into an INNER JOIN. 
-- WRONG: instruments without June trades disappear
FROM instruments i LEFT JOIN trades x ON x.instrument_id = i.instrument_id
WHERE x.trade_date >= '2026-06-01'
-- RIGHT: filter inside ON, so unmatched instruments are kept with NULLs (count 0)
FROM instruments i LEFT JOIN trades x
  ON x.instrument_id = i.instrument_id AND x.trade_date >= '2026-06-01'
Conditions on the left table still belong in WHERE.
Counting after a LEFT JOIN: COUNT(*) counts the NULL row as 1. Use COUNT(right_table.id) to get 0.
Fan-out: joining two one-to-many tables at once (employees→assignments and employees→orders) multiplies rows and inflates SUM/COUNT. Aggregate each child table in its own subquery first, then join.

11Window functions (MySQL 8)

function() OVER ( [PARTITION BY group_cols] [ORDER BY sort_cols] [frame] )

Like GROUP BY, but keeps every row and adds a computed column.

-- top 2 per department (exactly 2: ROW_NUMBER; keep ties: DENSE_RANK)
SELECT * FROM (
  SELECT e.*, ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC, emp_id) AS rn
  FROM employees e
) t
WHERE rn <= 2;
-- running notional per trader
SELECT trade_id, trader_id, trade_date,
       SUM(quantity * price) OVER (PARTITION BY trader_id ORDER BY trade_date
                                   ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running
FROM trades;

A window function can’t be used in WHERE, GROUP BY or HAVING at the same level, so wrap the query. Named windows: … OVER w … WINDOW w AS (PARTITION BY dept_id ORDER BY salary DESC).

13Classic query patterns

-- 1. Nth (2nd) highest distinct value
SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees);
SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1;
SELECT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) r FROM employees) t WHERE r = 2 LIMIT 1;

-- 2. Top N per group
SELECT * FROM (SELECT e.*, ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) rn FROM employees e) t WHERE rn <= 3;

-- 3. Row with the max per group (latest trade per trader)
SELECT x.* FROM trades x
JOIN (SELECT trader_id, MAX(trade_date) md FROM trades GROUP BY trader_id) m
  ON m.trader_id = x.trader_id AND m.md = x.trade_date;

-- 4. Duplicates
SELECT email, COUNT(*) FROM employees GROUP BY email HAVING COUNT(*) > 1;

-- 5. Anti-join: rows with no match
SELECT p.* FROM projects p LEFT JOIN assignments a ON a.project_id = p.project_id WHERE a.project_id IS NULL;
SELECT p.* FROM projects p WHERE NOT EXISTS (SELECT 1 FROM assignments a WHERE a.project_id = p.project_id);

-- 6. Exactly N / at least N
SELECT emp_id FROM assignments GROUP BY emp_id HAVING COUNT(*) = 1;

-- 7. "All of": employees assigned to EVERY project (relational division)
SELECT emp_id FROM assignments GROUP BY emp_id
HAVING COUNT(DISTINCT project_id) = (SELECT COUNT(*) FROM projects);

-- 8. Pivot with conditional aggregation
SELECT trader_id,
       SUM(CASE WHEN side = 'BUY'  THEN quantity ELSE 0 END) AS buys,
       SUM(CASE WHEN side = 'SELL' THEN quantity ELSE 0 END) AS sells,
       COUNT(CASE WHEN status = 'PENDING' THEN 1 END)        AS pending   -- COUNT ignores the NULL from a missing ELSE
FROM trades GROUP BY trader_id;

-- 9. Compare each row with its group average
SELECT * FROM (SELECT e.*, AVG(salary) OVER (PARTITION BY dept_id) dept_avg FROM employees e) t WHERE salary > dept_avg;

-- 10. Percentage of total
SELECT dept_id, ROUND(100 * SUM(salary) / SUM(SUM(salary)) OVER (), 1) AS pct FROM employees GROUP BY dept_id;

-- 11. Running total and day-over-day change
SELECT trade_date, SUM(quantity) q,
       SUM(SUM(quantity)) OVER (ORDER BY trade_date) AS running,
       SUM(quantity) - LAG(SUM(quantity)) OVER (ORDER BY trade_date) AS change_vs_prev
FROM trades GROUP BY trade_date;

-- 12. Delete duplicates, keep the lowest id
DELETE e1 FROM employees e1 JOIN employees e2 ON e1.email = e2.email AND e1.emp_id > e2.emp_id;

-- 13. Hierarchy (all reports under manager 1)
WITH RECURSIVE chain AS (
  SELECT emp_id, first_name, manager_id FROM employees WHERE emp_id = 1
  UNION ALL
  SELECT e.emp_id, e.first_name, e.manager_id FROM employees e JOIN chain c ON e.manager_id = c.emp_id
) SELECT * FROM chain;

UPDATE/DELETE without WHERE changes every row. In MySQL Workbench, safe updates mode (error 1175) blocks a WHERE that doesn’t use a key. Test the WHERE with a SELECT first, then run the change inside a transaction.

16Transactions, ACID, locking

START TRANSACTION;                 -- or BEGIN
UPDATE accounts SET bal = bal - 100 WHERE id = 1;
SAVEPOINT s1;
UPDATE accounts SET bal = bal + 100 WHERE id = 2;
ROLLBACK TO s1;                    -- undo only after s1
COMMIT;                            -- or ROLLBACK (undo everything since START)
SET autocommit = 0;                -- default 1: every statement commits by itself
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;    -- lock the row until COMMIT
  • ACID: Atomicity (all or nothing), Consistency (constraints hold), Isolation (concurrent transactions don’t interfere), Durability (committed data survives crashes, via the redo log).
  • Transactions need InnoDB (MyISAM has no transactions or foreign keys).
  • Implicit commit: DDL (CREATE, ALTER, DROP, TRUNCATE, RENAME) commits automatically and can’t be rolled back.
  • Isolation levels: READ UNCOMMITTED (dirty reads) < READ COMMITTED < REPEATABLE READ (InnoDB default) < SERIALIZABLE. SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
  • Deadlock (error 1213): two transactions each wait for the other’s lock; InnoDB rolls one back. Prevent: access tables/rows in the same order, keep transactions short, index the columns in your WHERE. Lock wait timeout (1205): waited too long for a lock.

  • Index columns used in WHERE, JOIN ON, ORDER BY and GROUP BY; foreign keys; high-selectivity columns.
  • Don’t index tiny tables, low-cardinality flags, or columns that are constantly updated. Every index slows INSERT/UPDATE/DELETE and uses space.
  • Index killers: a function on the column (YEAR(d)=…, LOWER(email)=…) · a leading wildcard LIKE '%x' · implicit type conversion (comparing a VARCHAR column with a number) · OR across different columns · a composite index used without its leftmost column.
  • Clustered index = the InnoDB primary key (rows stored in PK order, one per table). Secondary indexes store the PK to find rows.
  • Query hygiene: select only the needed columns (no SELECT *), filter early, use LIMIT for previews, avoid N+1 queries from application code, and keep statistics fresh (ANALYZE TABLE t). The slow query log finds the culprits.

18Stored procedures, functions, triggers (MySQL syntax)

DELIMITER //                                   -- change the statement terminator so ; can appear inside the body
CREATE PROCEDURE raise_dept(IN p_dept INT, IN p_pct DECIMAL(5,2), OUT p_rows INT)
BEGIN
  UPDATE employees SET salary = salary * (1 + p_pct / 100) WHERE dept_id = p_dept;
  SET p_rows = ROW_COUNT();
END //
CREATE FUNCTION annual(s DECIMAL(10,2)) RETURNS DECIMAL(12,2) DETERMINISTIC
BEGIN
  RETURN s * 12;
END //
CREATE TRIGGER trg_emp_audit AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
  IF NEW.salary <> OLD.salary THEN
    INSERT INTO salary_audit(emp_id, old_salary, new_salary, changed_at)
    VALUES (OLD.emp_id, OLD.salary, NEW.salary, NOW());
  END IF;
END //
DELIMITER ;
CALL raise_dept(3, 10, @n); SELECT @n;
SELECT first_name, annual(salary) FROM employees;
  • Procedure: called with CALL, can modify data, IN/OUT/INOUT parameters, can return result sets.
  • Function: returns one value, usable inside SELECT/WHERE.
  • Trigger: runs automatically BEFORE/AFTER INSERT/UPDATE/DELETE, for each row. NEW.col = the new value, OLD.col = the old value. Used for audit, validation, derived columns (maintaining integrity).
  • Event: scheduled SQL (CREATE EVENT … ON SCHEDULE EVERY 1 DAY), MySQL’s cron.
  • Variables: @user_var (session) vs DECLARE x INT (inside BEGIN…END).

21Method for written SQL questions

  1. Output: list exactly the columns asked for (full name? rounded? alias?).
  2. Tables: which tables hold those columns and the filters? Draw the key path (students → grades → courses). Ignore distractor tables.
  3. Join type: “all / including those with none” → LEFT JOIN from that table; otherwise INNER.
  4. Row filters → WHERE (or ON for the right table of a LEFT JOIN). Watch the wording: “strictly above” = >, “at least” = >=, “between” = inclusive.
  5. “Per / each / by” → GROUP BY (every non-aggregated column). Conditions on totals → HAVING.
  6. Ranking / top-N per group → window function in a derived table.
  7. Sort and limit: ORDER BY with a tie-breaker; LIMIT if asked.
  8. Edge cases: NULLs (COUNT(col), IFNULL), ties (ROW_NUMBER vs DENSE_RANK), duplicates (DISTINCT), empty groups (LEFT JOIN + COUNT(right.col)), date boundaries.
  9. Trace it against the sample data by hand; if the result is empty, say so.
