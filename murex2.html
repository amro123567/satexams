Symbolic mode (relative changes)

chmod go-rwx file1.txt    # remove ALL rights from group and others; owner unchanged

Error behaviour — the classic traps

By default bash does not stop when a command fails. not a command prints “command not found” (exit 127) and the next line still runs.
#!/bin/bash                    # called as: script.sh false
param=$1
if [[ $param == true ]]; then ext=.java; fi    # false → ext never set (empty)
not a command                  # error, but script continues
rm *$ext                       # becomes rm *  → deletes EVERY file in the directory
cd /opt/missing                # fails, you stay where you are
rm -rf *                       # runs in the WRONG directory
# safe: cd /opt/missing || exit 1
Defensive header: set -euo pipefail → -e exit on any error · -u error on unset variables (would have caught $ext) · -o pipefail a pipeline fails if any part fails. Always quote variables: "$file".
#!/bin/bash
RND="Random number is:$RANDOM"
echo "$RND"                    # prints ONE random number on the console
logger -p user.info "$RND"     # writes it to the SYSTEM log, facility user, priority info
x=5; [ $x -gt 3 ] && echo big || echo small     # → big
false && echo A || echo B                       # → B
echo $(( 7 / 2 ))   # → 3  (bash arithmetic is integer only)

The model: four places your code lives

Working directory ──git add──▶ Staging area (index) ──git commit──▶ Local repository ──git push──▶ Remote (origin)
        ◀──────────── git checkout / restore ────────────          ◀── git fetch / pull ──
  • Commit = snapshot of the staged files + message + author + pointer to parent commit(s). Identified by a SHA hash.
  • Branch = a movable pointer to a commit. HEAD = pointer to the current branch/commit. “Detached HEAD” = HEAD points to a commit, not a branch.
  • Untracked files are not in git at all until git add. Uncommitted changes in the working directory follow you when you switch branches (if no conflict).
  • HEAD~1 = first parent of HEAD (one commit back), HEAD~3 = three back. HEAD^2 = second parent (of a merge commit).

IPv4 addressing

  • IPv4 = 32 bits, written as 4 octets (0–255): 192.168.1.10. IPv6 = 128 bits, hex: 2001:db8::1.
  • An address has a network part and a host part, split by the subnet mask (e.g. 255.255.255.0 = /24, CIDR notation = number of network bits).
  • Network address = first address, host bits all 0 — identifies the network, not assignable. Broadcast address = last address, host bits all 1. Everything between = usable hosts.
  • Default gateway = router that forwards traffic leaving your subnet. MAC address = 48-bit hardware address (L2). ARP maps IP → MAC on the local network.
  • 127.0.0.1 = loopback / localhost (this machine). 0.0.0.0 = “all interfaces” when a server listens. 169.254.x.x = APIPA (DHCP failed).

Indexes & performance

  • An index is a separate structure (usually a B-tree) that lets the DB find rows without scanning the whole table (full table scan). Speeds up WHERE, JOIN, ORDER BY on indexed columns.
  • Cost: extra storage, and slower INSERT/UPDATE/DELETE (index must be maintained). Not useful on low-selectivity columns (gender) or tiny tables.
  • Clustered index: defines the physical order of the table rows; only one per table (usually the primary key). Non-clustered: separate structure with pointers to rows; many per table.
  • Unique index: also enforces uniqueness → solves both “slow search” and “duplicate invoice numbers”.
  • Composite index (a, b): helps queries filtering on a or a AND b (leftmost prefix), not b alone.
  • Covering index: contains all columns a query needs. Partitioning: split a huge table by range (e.g. by year) → partition pruning.
  • Index killers: functions on the column (WHERE YEAR(order_date)=2026), leading wildcard (LIKE '%x'), implicit type conversion, OR on different columns.

CREATE UNIQUE INDEX ux_invoice ON Sales(invoice_no);

DBMS theory & scaling

  • DBMS = software to store, organize, query and manage data (its primary function: let users store and retrieve data through queries; also handles security, integrity, concurrency, backup/recovery). RDBMS = relational: tables, rows, keys, SQL (Oracle, MySQL, PostgreSQL, SQL Server). NoSQL = document (MongoDB), key-value (Redis), column (Cassandra), graph (Neo4j) — flexible schema, horizontal scale.
  • OLTP (many small transactions, normalized) vs OLAP (analytics, aggregates, data warehouse, star schema).
  • Benefits of an RDBMS on multiple servers: high availability & failover (no single point of failure) · scalability/load balancing (read replicas, sharding) · performance · disaster recovery (replica in another site) · maintenance without downtime.
  • Replication: copies of data (master–slave/primary–replica, synchronous vs asynchronous). Sharding: split rows across servers by key. Clustering: Oracle RAC — several instances, one DB.
  • CAP theorem: a distributed system can guarantee at most two of Consistency, Availability, Partition tolerance.
  • Backup: full / incremental / differential; point-in-time recovery via logs.
  • SQL injection: user input concatenated into SQL (' OR 1=1 --). Prevent with prepared statements / bind variables.
  • Oracle specifics (Murex runs on Oracle/Sybase/SQL Server): DUAL table, ROWNUM, NVL, SYSDATE, VARCHAR2, MINUS, sequences, v$session, v$sql, EXPLAIN PLAN, AWR reports, ORA- error codes (ORA-00001 unique violated, ORA-00942 table doesn’t exist, ORA-01017 invalid login, ORA-00060 deadlock, ORA-01555 snapshot too old, ORA-12154 TNS can’t resolve service).

  • Overriding rules: same signature, same or covariant return type, access can’t be more restrictive, can’t throw broader checked exceptions. @Override makes the compiler verify.
  • Abstract class: can’t be instantiated, may have abstract and concrete methods, constructors, state. Interface: contract; methods public abstract by default (plus default/static since Java 8); fields are public static final; a class can implement many interfaces but extend one class.
  • final: variable can’t be reassigned · method can’t be overridden · class can’t be extended (e.g. String).
  • static: belongs to the class, shared by all instances; static methods can’t use this or instance fields directly.
  • Access: private (class) < default/package < protected (package + subclasses) < public.
  • Four pillars: encapsulation (private fields + getters), inheritance, polymorphism, abstraction.
  • equals()/hashCode() contract: equal objects must have equal hash codes (needed for HashMap/HashSet).
  • Casting: upcast implicit (Animal a = new Dog()); downcast explicit, wrong type → ClassCastException; check with instanceof.

Lifecycle & fundamentals

  • SDLC: requirements → design → implementation → testing → deployment → maintenance. Models: Waterfall (sequential), V-model (each dev phase paired with a test level), Agile/Scrum (sprints, continuous testing), DevOps (CI/CD).

Test design techniques

Equivalence partitioning (EP)

Split inputs into classes the system should treat the same; test one value per class. Age valid 18–60 → 3 partitions: <18 (invalid), 18–60 (valid), >60 (invalid) (+ non-numeric/empty).

Boundary value analysis (BVA)

Bugs hide at edges. For a boundary B test B−1, B, B+1 (3-value) or B−1, B (2-value). Range 18–60 → 17, 18, 19, 59, 60, 61.

Book offer at multiples of 5 up to 20 (5→$25, 10→$40, 15→$50, 20→$60): each price point is a boundary → 4,5,6 · 9,10,11 · 14,15,16 · 19,20,21, plus the lower edge of the domain 0,1 → 0, 1, 4, 5, 6, 9, 10, 11, 14, 15, 16, 19, 20, 21 (the most complete option).

Decision table

Conditions × actions; n binary conditions → 2ⁿ rules. Member (Y/N) × order > $100 (Y/N) → 4 rules.

Others

  • State transition: states + events (e.g. order: New → Paid → Shipped → Delivered; account locked after 3 failures).
  • Use case / scenario testing: main flow + alternate flows.
  • Error guessing: experience-based (empty, null, special characters, very long strings, 0, negative, leap year 29 Feb, time zones).
  • Pairwise: cover every pair of parameter values with few tests.

Hardware basics

  • CPU: few powerful cores, general-purpose, sequential logic. Clock speed (GHz), cores, threads (hyper-threading), cache L1/L2/L3. 32-bit (max 4 GB addressable) vs 64-bit.

Operating system concepts

  • Kernel: core of the OS — manages CPU scheduling, memory, devices, system calls. User space vs kernel space. Shell = command interpreter (bash).
  • Process = running program with its own memory space. Thread = unit of execution inside a process, shares its memory (lighter, but needs synchronization). Context switch = CPU switching between them.
  • Virtual memory: each process sees its own address space; pages mapped to RAM or swap on disk. Heavy swapping = “thrashing” = slow. Page fault = page not in RAM.
  • Scheduling: FCFS, round robin (time slices), priority, shortest job first.
  • Deadlock conditions (all four needed): mutual exclusion, hold and wait, no preemption, circular wait. Race condition: result depends on timing. Synchronization: mutex, semaphore, monitor.
  • IPC: pipes, sockets, shared memory, message queues, signals.
  • File systems: ext4, XFS (Linux), NTFS (Windows). Inode = file metadata. Windows vs Linux: \ vs /, CRLF vs LF line endings, case-insensitive vs case-sensitive names.

JVM: bytecode, GC, thread vs heap dumps

  • javac A.java → A.class = bytecode, which is portable because every OS/CPU has its own JVM that interprets and JIT-compiles it. (C → native binary, not portable.)
  • Heap generations: Young (Eden + Survivor; frequent minor GC) → Old/Tenured (long-lived objects). A full GC runs when the old generation/heap has no space left for allocation; it is slow and can pause the application (“stop the world”). System.gc() is only a request. An object becomes eligible for GC when nothing references it.
  • Collectors: Serial, Parallel, G1 (default), ZGC/Shenandoah (low pause). Flags: -Xms, -Xmx, -Xlog:gc.
  • Thread dump (jstack PID, kill -3 PID, jcmd PID Thread.print): the state and stack of every thread (RUNNABLE, BLOCKED, WAITING, TIMED_WAITING). Use it for hangs, deadlocks, high CPU. Several threads BLOCKED on the same monitor → deadlock/contention.
  • Heap dump (jmap -dump:format=b,file=h.hprof PID, -XX:+HeapDumpOnOutOfMemoryError): every object in memory and its references. Use it for memory leaks / OutOfMemoryError, analysed with Eclipse MAT or VisualVM.

Security concepts

  • Zero trust: “never trust, always verify”, regardless of network location. Authenticate and authorise every request, least privilege, MFA, micro-segmentation, encrypt everything. The opposite of perimeter security (“inside the firewall = trusted”).
  • IAM: Identity and Access Management controls authentication (who you are) and authorization (what you may do): users, groups, roles, policies.
  • Authentication vs authorization → HTTP 401 vs 403. MFA combines different factor types: something you know, have, or are.
  • Least privilege, separation of duties, encryption at rest and in transit (TLS), hashing passwords (bcrypt), the CIA triad (Confidentiality, Integrity, Availability).
  • Common attacks: SQL injection, XSS, CSRF, phishing, brute force, DDoS, man-in-the-middle.

ISTQB-style testing theory

  • Main goal of a test team: provide information and build enough confidence to decide whether to release. You can never prove the absence of faults.
  • Risk-based prioritisation: when time is short, run the high-impact/high-probability tests first. Setup and teardown steps (open/close DB) are needed by the others; changes that alter nothing (replace a value with the same value) and cosmetic edits come last.
  • Tester skills in agile: product/domain knowledge, being a good team player (collaboration, communication), critical thinking. The Product Owner owns the vision and backlog; the Scrum Master facilitates; the team plans its own work.
  • Agile testing: whole-team quality, testing inside the sprint, test automation pyramid (many unit tests, fewer API tests, fewest UI tests), definition of done, test-first (TDD/BDD/ATDD).
  • Field validation recipe (e.g. alphanumeric username, max 16): valid classes (letters, digits, mix, case), boundaries (0, 1, 15, 16, 17), invalid characters (special, spaces, Unicode, emoji), empty, duplicates/case-sensitivity, injection (SQL, XSS), client- and server-side validation, error messages, copy/paste, browsers/mobile.
  • Test timeout (a scenario exceeds its time limit): performance regression, slow or overloaded environment, hang/deadlock/waiting on a resource, larger data, an unrealistic limit.
